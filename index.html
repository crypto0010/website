Understanding Dynamic Coprime Labeling

What is Coprime Labeling?

Two integers are coprime if their greatest common divisor is 1: gcd(a, b) = 1. For example, 8 and 15 are coprime because gcd(8,15) = 1, but 8 and 12 are not because gcd(8,12) = 4.

A coprime labeling of a graph assigns positive integers to vertices such that every pair of adjacent vertices has coprime labels.

Example: Path graph P₅ with labels [2, 3, 5, 7, 11]
v₀=2 — v₁=3 — v₂=5 — v₃=7 — v₄=11

gcd(2,3) = 1 ✓   gcd(3,5) = 1 ✓   gcd(5,7) = 1 ✓   gcd(7,11) = 1 ✓

Since all primes are pairwise coprime, assigning distinct primes always works. But finding the minimum labels is NP-hard.

The Power Map g(x) = xᵐ

Dynamic Coprime Labeling adds a temporal dimension: vertex labels evolve over time. The canonical transformation is the power map:

fₙ₊₁(v) = fₙ(v)ᵐ

Theorem 2 (Coprimality Preservation): If gcd(a, b) = 1, then gcd(aᵐ, bᵐ) = 1. Therefore, if f₀ is a coprime labeling, then fₙ is a coprime labeling for all t ≥ 0.

Labels grow double-exponentially: fₙ(v) = f₀(v)^(m^t), motivating modular arithmetic for practical computation.

GPU Acceleration — Why CUDA?

DCL operations are embarrassingly parallel: each vertex/edge is independent. This maps perfectly to GPU architectures with thousands of CUDA cores executing in SIMT fashion.

#KernelParallelism

This static page shows pre-computed results and client-side demos. For the full experience with live GPU computation, graph editor, and all 6 operations, run the server locally:

# Clone and build
$ git clone https://github.com/crypto0010/website.git dcl-rs
$ cd dcl-rs && git checkout master
$ cargo run -p dcl-web

# Open in browser
http://localhost:3000
